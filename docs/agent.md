# Agent

Agent 本体在 `worker/src/sport-agent.ts`（Think harness）。三层构成：
**规则/人设**（只读 context block）→ **工具**（唯一能碰数据的手）→ **记忆**（长期）。

## 用户可见的指令

| 指令 | 别名 | 作用 |
|---|---|---|
| `/help` | `/start`、`帮助`、`你能干什么` | 用法速查 |
| `/status` | `水位`、`上下文` | 上下文水位：消息条数 + 估算 token + 记忆块大小（不调模型，零 token 开销） |
| `/new` | `重新开始`、`新对话` | 清空聊天记录并取消排队中的提交；**长期画像保留** |

## 12 个工具

**查**（只读，随便调）

| 工具 | 用途 |
|---|---|
| `get_summary` | 近 N 天分项画像（跑步/骑行分开），默认 30 天 |
| `query_workouts` | 按类型/日期区间查明细（含 id），改数前必须先查 |
| `stats_workouts` | 按月/年聚合：次数、跑量、均配速、均心率 |
| `trends` | 配速/心率/跑量按周或按月的趋势序列（问「有没有进步」用这个） |
| `records` | PB 榜：最长单次、最快配速（≥3km）、单月最高跑量、累计 |
| `compare_periods` | 两段时间对照，直接给变化百分比 |
| `streaks` | 当前连续天数、历史最长、活跃天数 |

**写**（全部两阶段：先预览，用户确认后才落库）

| 工具 | 用途 |
|---|---|
| `update_workout` | 按 id 改字段（白名单 10 个字段） |
| `delete_workout` | 按 id 删（删后 git 可 revert） |
| `append_workout` | 纯文字补录（「昨天跑了 5 公里」） |
| `list_review` | 列出待确认的截图识别项 |
| `confirm_review` | 把某条待确认项确认入库，写成功后自动删掉 review 文件 |

**写不了的东西**：`workspace` 的文件工具（读写删改查）一律关闭 —— 数据不在
workspace 里，开着只会让模型乱试。缺 `GH_PAT` 时全部写操作明确回「只读模式」，
不会假装成功。

## 记忆

三层，都在 Durable Object SQLite 里，**不进数据仓**：

1. **对话历史** —— 自动管理，配合上下文压缩；
2. **`user_profile`** —— 长期画像：目标距离、伤病史、作息偏好、装备。
   模型用 `set_context` 更新，最多 1500 token；
3. **`coaching_notes`** —— 教练备忘：弱项、上次建议的执行情况、下次要提醒的事，
   最多 1500 token。

`/new` 只清第 1 层，2/3 层保留 —— 换话题不用重新自我介绍。

### 上下文压缩

- 阈值 **32 万 token**（40 万窗口的 80%）。太早压没意义，压了也白压；
- 压法：中间对话交给模型总结成摘要，**最近约 2 万 token 原文保留**；
- 摘要生成失败只打日志跳过，不阻塞对话；
- 画像/备忘块不参与压缩；
- `/status` 能看到当前水位，消息数一路涨就该 `/new`。

> 注意：单次**输出**上限是 50k token，跟上下文压缩是两件事。
> 问得极长时先撞的是输出上限（回答被截断），那个只能靠分段提问解决。

## 行为准则（写在 `rules` 只读块里）

- **数据铁律**：只用工具查到的数据说话；问具体某条/某天/某月/某年/最早/最晚时
  必须先查工具，工具能查到的以工具为准，**绝不允许凭印象说「不知道」**；
- **改库铁律**：改/删/补录统一两步 —— 先预览念给用户，用户明确说「确认」后
  再用相同参数带 `confirmed=true` 调一次；
- **工具边界**：运动数据只许用上面那 12 个工具读写；
- **失败要说话**：工具报错要如实转述，不许把失败说成「没有数据」（这是最要命的
  幻觉来源）；
- 只谈训练恢复，不越界做医疗诊断。

## 通道

- **Telegram**：`/tg` webhook，`TG_SECRET` 校验 + `claimUpdate` 去重；
- **飞书**：`/feishu` 事件订阅，代码已就绪但**尚未配置** `FEISHU_APP_ID/SECRET`，
  属于未验证路径；
- **网页版**：`POST /api/chat`，参数 `{session, key, text}`。
  会话限流 60 轮/小时，`key` 用于重推去重（重复 key 返回 409 让你换一个）。
  前端不接触任何模型密钥。

## 截图识别链路

发图 → 下载原图 → 提交到 `images/YYYY/MM/` → 用 https 地址调 Vision →
按 `confidence` 路由：

- **≥ 0.8**：直接追加进当年 CSV（`source=image`），回「已入库」；
- **< 0.8**：写 `review/needs-review-*.json`，回「没看清，已进待确认」，
  之后可以问它「有没有待确认的」，它会用 `list_review` + `confirm_review` 处理；
- **Vision 挂掉**：图照样先入库，同时写 review 记录，避免图变孤儿。

**发原图更准**：直接「拍照」发送时 Telegram 会把长截图压到最长边 1280，
小字会糊；点回形针选「文件」方式发原图，识别率明显更高。
