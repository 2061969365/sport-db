# Agent

Agent 本体在 `worker/src/sport-agent.ts`（Think harness）。三层构成：
**规则/人设**（只读 context block）→ **工具**（唯一能碰数据的手）→ **记忆**（长期）。

## 用户可见的指令

| 指令 | 别名 | 作用 |
|---|---|---|
| `/help` | `/start`、`帮助`、`你能干什么` | 用法速查 |
| `/status` | `水位`、`上下文` | 上下文水位：消息条数 + 估算 token + 记忆块大小（不调模型，零 token 开销） |
| `/new` | `重新开始`、`新对话` | 清空聊天记录并取消排队中的提交；**长期画像保留** |

## 22 个工具

**查运动数据**（只读，随便调）

| 工具 | 用途 |
|---|---|
| `get_summary` | 近 N 天分项画像（跑步/骑行分开），默认 30 天 |
| `query_workouts` | 按类型/日期区间查明细（含 id），改数前必须先查 |
| `stats_workouts` | 按月/年聚合：次数、跑量、均配速、均心率 |
| `trends` | 配速/心率/跑量按周或按月的趋势序列（问「有没有进步」用这个） |
| `records` | PB 榜：最长单次、最快配速（≥3km）、单月最高跑量、累计 |
| `compare_periods` | 两段时间对照，直接给变化百分比 |
| `streaks` | 当前连续天数、历史最长、活跃天数 |

**时间与联网**

| 工具 | 用途 | 依赖 |
|---|---|---|
| `current_time` | 当前北京时间 + 星期 + ISO 周，可带偏移天数算「下周六」 | 无 |
| `weather` | 1~7 天日预报（温度/降水概率/风速），安排户外训练前调 | open-meteo，免 Key |
| `web_search` | 全网搜索，首选 **AnySearch**；不可用时降级 Tavily → DDG → 维基 | AnySearch 匿名可用 |
| `fetch_url` | 读网页正文，首选 **AnySearch `/v1/extract`**（能读 JS 页面），失败再自己抓 HTML 剥标签 | AnySearch 匿名可用 |

> **搜索已接 AnySearch**（`POST https://api.anysearch.com/v1/search`）：匿名即可用，
> 实测从 Cloudflare 出口可达、返回真实中文结果（含政府/官网来源）。
> 想用凭据额度（更稳更高配额）就 `npx wrangler secret put ANYSEARCH_API_KEY`。
>
> 降级链仍有意义：AnySearch 挂了 → Tavily（若配了 Key）→ DuckDuckGo → 维基百科。
> 实测 DDG/Mojeek 对 Cloudflare 出口返反爬页，属于已知兜底而非主路。
> 无论走哪级都标明来源；没搜到就如实说「没联网搜到」，**绝不许编**。

**仓库文件**（只读 + 受限写）

| 工具 | 用途 |
|---|---|
| `list_repo_dir` | 列仓库目录（`plans/`、`reports/daily/`、`data/`、`docs/`），看有什么文件 |
| `read_repo_file` | 读仓库里的文本文件（日报、计划、文档、CSV） |
| `write_plan` | 把训练计划写进 `plans/*.md`（两阶段确认，**只能写这个目录**，碰不到 `data/`） |

**定时提醒**

| 工具 | 用途 |
|---|---|
| `set_reminder` | 到点自动推消息：`2026-10-17 07:00` / `+2h` / `+1d` / cron `0 7 * * *`（每天 7 点） |
| `list_reminders` | 列出已设提醒（含 id） |
| `cancel_reminder` | 按 id 取消 |

> 提醒由 Durable Object 的持久化调度器执行，Worker 不在线也会到点触发；
> 一次性提醒推完自动清理。**Telegram / 飞书能主动推**；网页版没有主动推送通道，
> 提醒会写进「最新回复」，下次打开页面或轮询时看到。

**写运动数据**（全部两阶段：先预览，用户确认后才落库）

| 工具 | 用途 |
|---|---|
| `update_workout` | 按 id 改字段（白名单 10 个字段） |
| `delete_workout` | 按 id 删（删后 git 可 revert） |
| `append_workout` | 纯文字补录（「昨天跑了 5 公里」） |
| `list_review` | 列出待确认的截图识别项 |
| `confirm_review` | 把某条待确认项确认入库，写成功后自动删掉 review 文件 |

**写不了的东西**：`workspace` 的内置文件工具与 `bash` 一律关闭 —— 数据不在 workspace
里（在 GitHub），开着只会让模型乱试路径；要读写文件就走上面三个仓库文件工具。
缺 `GH_PAT` 时全部写操作明确回「只读模式」，不会假装成功。

## 记忆

三层，都在 Durable Object SQLite 里，**不进数据仓**：

1. **对话历史** —— 自动管理，配合上下文压缩；
2. **`user_profile`** —— 长期画像：目标距离、伤病史、作息偏好、装备。
   模型用 `set_context` 更新，最多 1500 token；
3. **`coaching_notes`** —— 教练备忘：弱项、上次建议的执行情况、下次要提醒的事，
   最多 1500 token。

`/new` 只清第 1 层，2/3 层保留 —— 换话题不用重新自我介绍。

### 上下文压缩

- 阈值 **32 万 token**（40 万窗口的 80%）。太早压没意义，压了也白压；
- 压法：中间对话交给模型总结成摘要，**最近约 2 万 token 原文保留**；
- 摘要生成失败只打日志跳过，不阻塞对话；
- 画像/备忘块不参与压缩；
- `/status` 能看到当前水位，消息数一路涨就该 `/new`。

> 注意：单次**输出**上限是 50k token，跟上下文压缩是两件事。
> 问得极长时先撞的是输出上限（回答被截断），那个只能靠分段提问解决。

## 行为准则（写在 `rules` 只读块里）

- **数据铁律**：只用工具查到的数据说话；问具体某条/某天/某月/某年/最早/最晚时
  必须先查工具，工具能查到的以工具为准，**绝不允许凭印象说「不知道」**；
- **改库铁律**：改/删/补录统一两步 —— 先预览念给用户，用户明确说「确认」后
  再用相同参数带 `confirmed=true` 调一次；
- **工具边界**：运动数据只许用那 12 个数据工具读写；时间/联网（4 个）、仓库文件（3 个）、
  提醒（3 个）是查外部信息和存计划的正路，不许假装用过；
- **计划留存**：排好完整计划后主动问要不要存进仓（`write_plan` → `plans/`），
  以后用户问「我的计划」就 `read_repo_file` 读出来，别凭记忆复述；
- **失败要说话**：工具报错要如实转述，不许把失败说成「没有数据」（这是最要命的
  幻觉来源）；
- **计划纪律**：要计划时按序执行 —— 先 `current_time` 定今天 → `get_summary`/`trends`
  看真实负荷 → 户外计划查 `weather` → 需要外部信息才 `web_search`；
  输出要分周期分天、写清距离/配速区间/强度意图，数据不足就先要信息，别套通用模板；
- **表达纪律**：只在最终答复里说话，工具调用间隙不许输出「收到/我来帮你查」这类旁白
  （用户只看到最后一条答复，中间的话会变成碎片粘在开头）；
- 只谈训练恢复，不越界做医疗诊断。

## 通道

**长问题是异步的**：要一份训练计划会跑 30 秒到几分钟，同步等答复会撞平台超时
（实测稳定 80.7 秒断连，用户什么都收不到）。所以三条通道都改成
「提交后立刻返回 + turn 完成时由 `onChatResponse` 推回」：

| 通道 | 入口 | 回复方式 |
|---|---|---|
| Telegram | `POST /tg`（`TG_SECRET` 校验 + `claimUpdate` 去重） | webhook 立刻 200；跑完由 hook 发回 TG，期间刷新「正在输入」 |
| 飞书 | `POST /feishu` 事件订阅 | 同上，跑完经飞书 API 推；**尚未配置 App ID/Secret，属未验证路径** |
| 网页版 | `POST /api/chat` `{session,key,text}` | 快问题当场返回答复；超 70 秒返回 `202 {pending,since}`，前端轮询 `GET /api/chat/result?session=&since=` |

网页版会话限流 60 轮/小时，`key` 用于重推去重（重复 key 返回 409）。
前端不接触任何模型密钥。

## 截图识别链路

发图 → 下载原图 → 提交到 `images/YYYY/MM/` → 用 https 地址调 Vision →
按 `confidence` 路由：

- **≥ 0.8**：直接追加进当年 CSV（`source=image`），回「已入库」；
- **< 0.8**：写 `review/needs-review-*.json`，回「没看清，已进待确认」，
  之后可以问它「有没有待确认的」，它会用 `list_review` + `confirm_review` 处理；
- **Vision 挂掉**：图照样先入库，同时写 review 记录，避免图变孤儿。

**发原图更准**：直接「拍照」发送时 Telegram 会把长截图压到最长边 1280，
小字会糊；点回形针选「文件」方式发原图，识别率明显更高。
